# API Design Standards

- **Error format**: `{"error": {"code": "...", "message": "..."}}` on every non-2xx response (`internal/httpserver/respond.Error`). Not RFC 7807 — kept as a simpler flat envelope for this template. Known codes: `validation_error`, `unauthorized`, `not_found`, `conflict`, `internal_error`, `rate_limited`. Panics are caught by `middleware.Recoverer` and returned in this same envelope (`internal_error`, 500) so clients never see a bare/empty 500.
- **Pagination**: `?page=&page_size=` on `GET /api/v1/articles`, capped at `page_size<=100` (`internal/articles/handler.go`); response includes `total`/`page`/`page_size`.
- **Rate limiting**: Redis-backed fixed-window counter (`internal/httpserver/middleware/ratelimit.go`), implemented as a single atomic Lua script (INCR + conditional EXPIRE) to avoid a key ending up with no TTL if the process dies between the two calls. IP-keyed on `/api/v1/auth/register` and `/api/v1/auth/login` (10 req/min; the IP comes from `middleware.RealIP`, which only honors `X-Forwarded-For` from peers inside `TRUSTED_PROXIES` — see [deployment.md](deployment.md)); user-keyed (post-auth) on article writes — create/update/delete/publish (30 req/min). **Fails open**: if Redis is unreachable, the middleware logs the error at `Error` level and allows the request through rather than blocking it — rate limiting is treated as an abuse-prevention nice-to-have, not a hard dependency the whole auth/write surface should go down with.
- **Idempotency**: not implemented in this version — flagged here as a gap, not falsely claimed as done. There is no idempotency-key mechanism on any write endpoint.
- **CORS**: `internal/httpserver/middleware/cors.go`, mounted globally in `NewRouter`, driven by `CORS_ALLOWED_ORIGINS` (comma-separated, exact origin match). **Empty by default, which disables CORS entirely** — no CORS headers are emitted, so browsers enforce same-origin. Set it to your frontend origin(s) to enable. `*` is deliberately not special-cased: responses set `Access-Control-Allow-Credentials: true`, which browsers reject alongside a wildcard origin. Preflight `OPTIONS` requests for allowed origins short-circuit with 204.
- **Auth**: `Authorization: Bearer <access_token>`; obtain via `POST /api/v1/auth/register` or `POST /api/v1/auth/login`, refresh via `POST /api/v1/auth/refresh` (rotates the refresh token — the old one is invalidated on use).
- **API docs**: generated by swaggo/swag from handler annotations, served as Swagger UI at `/api/docs`. `/health/live` and `/health/ready` are deliberately excluded from the generated spec — they're unversioned infra probes mounted outside `/api/v1`, and annotating them would make Swagger UI advertise `/api/v1/health/...` URLs the server doesn't actually serve.
- **Request logging**: every request produces one structured `slog` record (`method`, `path`, `status`, `bytes`, `duration`, `request_id`, `remote_ip`) via `middleware.SlogLogger`. Level follows the status: 5xx → `Error`, 4xx → `Warn`, otherwise `Info`.
- **Middleware order** (`internal/httpserver/router.go`): `RequestID → RealIP → Recoverer → SlogLogger → CORS`, then route-specific `RateLimit`/`JWTAuth`.
